    How BeatIt works
    
        
    BeatIt builds a clinical case assessment from your stored documents. Start with the three steps below, then explore each tab when you need it.
    

        
    
          
          
          
        
    
      
    

      
    
        Home — your medical record
        
    
          
    The Home tab is the official case view. After you run analysis you get:
    
          
      
            
    • Executive summary — short overview with source citations.
      • 
            
    • Full assessment — detailed synthesis from your documents.
      • 
            
    • Open items — gaps and follow-ups to resolve. Tap Explore on a row to investigate.
      • 
          
    
          
    The status line at the top shows document count and open items. Use Export PDF to download the assessment.
    
          
    
            
          
    
        
    
      
    

      
    
        Open items — resolve gaps
        
    
          
    Open items are prioritized questions still missing from the record — staging details, missing labs, unclear pathology, and similar.
    
          
      
            
    • Tap Explore to run a focused investigation.
      • 
            
    • Review the draft, edit if needed, then Accept findings or save as a comment.
      • 
            
    • Mark an item Resolve when it is closed.
      • 
          
    
          
    
            
          
    
        
    
      
    

      
    
        AI Chat — live guided analysis
        
    
          
    Use the AI Chat tab for deep, multi-turn discussion of treatment pathways. It reads your library selection and the current Home assessment, then lets you steer.
    
          
      
            
    • Start with a broad compare, then ask to go deeper on one regimen, trial class, biomarker, or surgical decision.
      • 
            
    • Starter prompts are available for common deep dives.
      • 
            
    • Chat sessions are saved so you can continue later. This does not replace the Home assessment.
      • 
          
    
          
    
            
          
    
        
    
      
    

      
    
        Custom Tasks — ask your own questions
        
    
          
    Custom analyses (trial lists, regimen comparisons, focused questions) run as drafts first. They do not change Home until you promote them.
    
          
      
            
    • Run a task from the Custom Tasks tab or from More options on Home.
      • 
            
    • Add optional notes at the bottom of a draft. Use PDF or Share to send to collaborators.
      • 
            
    • List items show Sources — library documents link to originals; otherwise it says when nothing is stored.
      • 
            
    • When finished, review the draft and tap Add to medical record or Discard draft.
      • 
            
    • For trial searches, fill in patient context in Settings first — line of therapy and biomarkers help tailor results.
      • 
          
    
          
    
            
          
    
        
    
      
    

      
    
        Library — documents & uploads
        
    
          
    Everything you store lives here. Use Add documents to bring in:
    
          
      
            
    • Clinical notes — paste visit notes, pathology, imaging summaries.
      • 
            
    • PDFs & URLs — reports and web pages.
      • 
            
    • DICOM / imaging — upload .dcm or .dicom slices (or a whole study folder).
      • 
            
    • YouTube — caption-based transcripts when available.
      • 
          
    
          
    Open a document to read extracted text, set a citation display name, or remove it.
    
          
    
            
            
          
    
        
    
      
    

      
    
        Source citations — read the tags
        
    
          
    Colored shorthand tags show where each claim comes from:
    
          
      
            
    • Doc Clinical record from stored files
      • 
            
    • Diag Imaging or pathology
      • 
            
    • Ctx Patient context from Settings
      • 
            
    • AI AI inference — verify independently
      • 
            
    • ? Not in your library — not backed by a stored record
      • 
          
    
          
    Superscript numbers link to reference lists. Customize badge labels under Settings → Source labels.
    
        
    
      
    

      
    
        History, Settings & audit
        
    
          
      
            
    • History — past assessments, newest first.
      • 
            
    • Settings — patient context, source label names, LLM model.
      • 
            
    • Audit trail — who changed what: uploads, analyses, comments, sign-ins.

    Clinical reviewer context
    
        
    Persona and synthesis instructions for every analysis. Default: general clinical reviewer (specialty inferred from the case as needed). Controls how the model reads and integrates all selected documents.
    
        
        
    
          Prepended to the system prompt for baseline, custom tasks, and investigations
          
    
            
            
          
    
        
    
      
    
      
    
        
    🦆
    
        
    Patient & case context
    
        
    Case-specific facts used in every medical analysis. Update as you learn more.
    
        
    Add whatever matters for this case (diagnoses, history, goals). For oncology trial searches, include line of therapy, biomarkers, ECOG, and prior treatments when known.
    

        

        
    
          Cited as [SOURCE: Patient context] when used in assessments. Wrong context causes wrong assessments.
          
        
    
      
    
      
    

      
    
      
    
        
    Source labels
    
        
    Customize shorthand badges and display names used in assessments, references, and the library. Source links and audit trail stay tied to the underlying records.
    
        
    
        
    
          Shown as colored tags like Diag beside citations
          
        
    
      
    
      
    

      
    
      
    
        
    LLM settings
    
        
    Baseline and custom tasks use the text Ollama model when the VM is reachable (LLM_PROVIDER=auto). The Imaging tab uses a separate vision model. OpenRouter is the cloud fallback (and default on Render).
